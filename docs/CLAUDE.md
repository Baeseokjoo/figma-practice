# CLAUDE.md

서울시립미술관 **전시해설 일정 탐색 UI/UX 개선 및 웹 접근성(KWCAG 2.2 / KRDS) 강화** 프로젝트.
요구사항 원문은 `docs/prd.md`이며, 이 파일과 충돌하면 PRD를 따르되 사용자에게 알린다.

---

## 1. 사용자

- 이 서비스는 **코딩 초보자**가 만드는 서비스다.
- 모든 답변과 설명은 **한국어**로, 전문용어는 쉬운 말로 풀어서 설명한다.
- 코드를 바꿀 때는 **무엇을, 왜** 바꿨는지 짧게 설명한다. 한 번에 너무 많은 파일을 바꾸지 않는다.
- 사용자가 직접 해야 하는 작업(명령어 실행 등)은 그대로 복사해 쓸 수 있게 단계별로 안내한다.
- **모르거나 애매한 부분은 추측하지 말고 먼저 질문한다.** PRD에 "추가 확인 필요"로 표시된 항목도 마찬가지다.

## 2. 기술 스택 (변경 금지)

| 구분 | 사용 기술 |
|---|---|
| 프레임워크 | React 19 |
| 빌드 도구 | Vite 8 |
| 언어 | JavaScript (`.jsx`) — TypeScript 사용 안 함 |
| 스타일 | 기본 CSS (CSS 변수 기반) — Tailwind, styled-components, CSS Modules, Sass 사용 안 함 |
| 폰트 | Pretendard — 로컬 파일 `src/fonts/*.woff2` (Regular 400 / Medium 500 / SemiBold 600), `src/styles/fonts.css`에서 등록. CDN 사용 안 함 |
| 린트 | oxlint |

```bash
npm run dev      # 개발 서버 실행
npm run build    # 배포용 빌드 (작업 후 오류 확인용)
npm run lint     # 코드 검사
```

- 위 스택을 바꾸거나 다른 라이브러리로 대체하지 않는다.
- 새 패키지(npm 라이브러리)가 필요하면 **설치 전에 이유를 설명하고 허락을 받는다.**

## 3. 디자인 규칙

### 디자인 구현 방식
- 화면 디자인은 **추후 Figma MCP를 통해** 시안을 읽어서 구현한다. 시안이 없는 화면을 임의로 디자인하지 않는다.
- Figma 파일: `https://www.figma.com/design/iICtp4r7wLJJ0eTOV8Xf9c` (공공기관 개선)
  - 완성 시안: 페이지 `3-4.완성본` › 섹션 `Mobile` (node `404:4386`)
  - 개발 전달 문서: 페이지 `핸드오프문서` (node `918:3`)
- 반응형 상세 디자인은 사이즈별 Figma 링크로 전달된다. 시각적 결과는 시안과 맞추되 아래 단위 규칙으로 변환한다.
- Figma 레이어명 오타는 코드에서 올바른 이름으로 쓴다: Foam→Form, Resalt→Result, Calender→Calendar, Dispaly→Display, Boder→border

### 디자인 토큰
- 색상·폰트·간격·라운드·그림자는 `src/styles/tokens.css`의 CSS 변수만 사용한다. **값을 직접 적지 않는다.**
- 컬러는 의미 기반 토큰 사용: `--text-main`, `--text-sub`, `--text-primary`, `--bg-base`, `--bg-info`, `--border-base` 등. `--color-*`(기본 색)와 `--primitive-*`(원본 값)는 컴포넌트에서 직접 쓰지 않는다.
- 텍스트는 Figma 텍스트 스타일과 같은 `font: var(--font-heading-title)` 형태로 적용한다.
- 간격 `--spacing-*`, 글자 크기 `--text-size-*`, 행간 `--text-line-height-*`는 데스크탑에서 자동으로 값이 바뀌므로 컴포넌트에서 다시 정의하지 않는다.
- Figma에서 변수 연결 없이 쓰였더라도 토큰과 같은 값(예: 16px, 10px, 4px)이면 **토큰으로 연결**한다.
- 테두리 두께 `1px`은 토큰 없이 직접 쓴다.
- 시안에 있는데 토큰에 없는 값이 나오면 새로 만들기 전에 사용자에게 묻는다.

### 반응형
- **브레이크포인트:** 모바일 0~1023px / 데스크탑 1024px 이상
- **모바일 우선:** 기본 스타일은 모바일 기준, 데스크탑은 `@media (min-width: 1024px)`로 확장한다. `max-width` 미디어쿼리는 쓰지 않는다.
- PC는 상단 고정 필터바, 모바일은 상단 접이식 복합 필터바

### 단위
- 레이아웃은 상대단위(`%`, `rem`) 사용, 고정 px 너비 지양. 브레이크포인트만 px로 표기
- **`em` 단위 사용 금지**
- `html`에 font-size를 지정하지 않는다 (1rem = 16px 유지, 사용자 글자 크기 설정 존중)
- Figma의 px 값은 `rem = px ÷ 16`으로 변환 (예: 44px → 2.75rem)
- 데스크탑 콘텐츠 영역은 `max-width: var(--content-max)` (임시 80rem) + 가운데 정렬

### 접근성 (KWCAG 2.2 / KRDS P0 필수)
- 320px 너비(400% 확대)에서도 가로 스크롤 없이 모든 기능 이용 가능
- 버튼·링크 터치 영역 최소 `var(--touch-min)` (2.75rem × 2.75rem)
- 3px 이상의 선명한 포커스링 (`:focus-visible`)
- **상태는 색상만으로 구분하지 않는다.** 텍스트·테두리·패턴·배지를 함께 쓴다.
- `--text-third`(#A1A1A1)는 본문 글자색으로 쓰지 않는다 (대비 부족)
- 시맨틱 HTML 우선 (`button`, `label`, `nav`, `main`), 모든 입력에 `<label>` 연결
- 아이콘만 있는 버튼은 `aria-label`, 아코디언은 `aria-expanded`, 드롭다운·달력은 ESC로 닫히고 닫힌 뒤 원래 버튼으로 포커스 복귀

### 문구 (공공언어)
- 화면 문구에 IT 전문용어(쿼리, 파라미터, 컴포넌트 등) 사용 금지
- 예: '검색 조건 초기화', '날짜 선택하기', '관람 가능일'

### 시각적 우선순위
1. '날짜 + 분관' 복합 필터바 및 실행/초기화 버튼
2. 전시해설 일정 카드 (분관명, 전시명, 해설 시간)
3. 입력 형식 도움말 및 범례 배지

## 4. 서비스 구조

### 목표 (KPI)
1. 탐색 과업 **3단계 이내**, 재검색 시간 50% 이상 단축
2. 날짜·필터 조작 시 입력 오류 평균 0회
3. 뒤로가기·URL 공유 시 검색 조건 보존율 **100%**
4. KWCAG 2.2 및 KRDS 필수(P0) 규격 100% 충족

### 사용자 흐름
1. **진입:** 상단 '날짜 + 분관' 복합 필터바로 바로 진입
2. **필터 설정:** 분관 선택 → 날짜 선택 (YYYY-MM-DD 도움말, 범례로 구분된 달력). 잘못 고르면 일괄 초기화
3. **결과 확인:** 조건에 맞는 전시해설 목록 → 상세 페이지 이동
4. **복귀·공유:** 뒤로가기·URL 공유 시 검색 조건 그대로 유지

### 기능 요구사항
| ID | 기능 | 핵심 |
|---|---|---|
| FR-01 | 복합 필터 | 분관(6개) 드롭다운 + 달력을 하나의 필터바로 통합. 단일일/범위 선택 |
| FR-02 | 필터 일괄 초기화 | 분관·날짜 조건을 버튼 1회로 원복 |
| FR-03 | 입력 도움말 & 라벨 | `<label>` 연결, `YYYY-MM-DD` 도움말 상시 노출. 오입력 시 "YYYY-MM-DD 형식으로 입력해주세요." |
| FR-04 | 날짜 상태 구분 | 오늘=두꺼운 테두리+'오늘', 선택일=반전 배경+'선택됨', 휴관일=사선 패턴+'휴관' 배지 |
| FR-05 | URL 상태 동기화 | 필터 상태를 주소창 쿼리와 동기화 (예: `?branch=north&startDate=2026-10-24`) |
| FR-06 | 예외 처리 | 휴관일/0건: "선택하신 날짜는 정기 휴관일입니다." + "가장 가까운 관람 가능일 보기". 네트워크 오류: "일정 정보를 불러오지 못했습니다. 잠시 후 다시 시도해주세요." + 재시도 버튼 |

### 아직 정해지지 않은 것 (구현 전 반드시 질문)
- 범위 선택 ↔ 단일일 선택 전환 방식과 기본값
- 초기화 후 화면 기본 상태
- 잘못된 URL 값이 들어왔을 때 처리 방식
- 일정 데이터를 어디서 가져올지 (API 주소, 데이터 형식)
- 키보드·스크린리더 세부 요구사항

### 폴더 구조
```
src/
├── components/        # 재사용 컴포넌트 (컴포넌트 1개 = 파일 1개, PascalCase.jsx)
├── fonts/             # Pretendard woff2 (Regular / Medium / SemiBold)
├── styles/
│   ├── fonts.css      # @font-face 등록 (src/fonts 연결)
│   ├── tokens.css     # 디자인 토큰 (Figma 변수·스타일에서 추출)
│   ├── reset.css      # 브라우저 기본 스타일 초기화
│   └── base.css       # body 폰트·배경색, 제목·링크·포커스링 기본 스타일 (토큰 변수만 사용)
├── index.css          # 전역 스타일 진입점: fonts → tokens → reset → base 순서로 @import
├── App.jsx
└── main.jsx           # index.css 불러오기
docs/prd.md            # 제품 요구사항 정의서
```
- 새 폴더(예: `pages/`, `hooks/`, `utils/`)가 필요하면 만들기 전에 사용자에게 알린다.

## 5. 안전 규칙

- **파일 삭제·덮어쓰기 전에 반드시 사용자에게 확인한다.** 특히 `docs/`, `CLAUDE.md`, 설정 파일(`package.json`, `vite.config.js`)
- 기술 스택 변경, 새 패키지 설치, 설정 파일 수정은 **허락을 받은 뒤** 진행한다.
- 요청받지 않은 기능 추가·대규모 리팩터링을 하지 않는다. 요청 범위만 작업한다.
- 코드 변경 후 `npm run build`로 오류가 없는지 확인하고, 실패하면 숨기지 말고 그대로 알린다.
- API 키·비밀번호 같은 민감 정보를 코드에 직접 넣지 않는다. 필요하면 `.env` 사용을 안내한다 (`.env`는 git에 올리지 않음).
- Figma 파일은 **읽기 위주**로 사용한다. Figma 디자인을 수정·삭제해야 할 때는 먼저 묻는다.
- git 커밋·푸시는 사용자가 요청할 때만 한다.
- 되돌리기 어려운 명령(`rm -rf`, `git reset --hard`, 강제 푸시 등)은 실행하지 않는다.
