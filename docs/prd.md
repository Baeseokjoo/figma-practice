# 제품 요구사항 정의서 (PRD)

## 1. 문서 개요 (Document Overview)

**프로젝트명:** 서울시립미술관 전시해설 탐색 UI/UX 개선 및 웹 접근성(KWCAG 2.2 / KRDS) 강화 프로젝트

**개선 타스크:** Task-1 탐색 효율성 및 상태 유지 – 접근성 높은 날짜/달력 인터랙션

### 프로젝트 목적
고령자, 저시력자, 모바일·키보드 이용자를 포함한 모든 관람객이 원하는 분관과 날짜의 전시해설 정보를 최소한의 조작으로 탐색하고, 상세 보기 후 뒤로가기나 URL 공유 시에도 검색 필터 상태가 유지되는 포용적이고 효율적인 웹 환경을 구축한다.

### 현황 및 문제점
- 6개 분관의 전시해설 정보가 한 화면에 나열되어 긴 스크롤과 인지적 피로가 발생함
- 현황표 상세 데이터는 원문에서 누락됨 → **추가 확인 필요**

| 번호 | 발견된 문제점 |
|---|---|
| 1 | 탐색 단계 과다 및 분관 정보 무분별 나열 (탐색 시간 지연) |
| 2 | 날짜 입력창 도움말 부재 (오입력 발생) |
| 3 | 날짜 상태를 색상 차이로만 구분하여 식별 어려움 |
| 4 | 검색 상태 미보존 (상세 보기 후 뒤로가기 시 필터 초기화) |
| 5 | 필터 오설정 시 개별 삭제가 필요하여 조작 피로 발생 |

### 테마 구조화
| 테마 | 비고 |
|---|---|
| 테마 1. 탐색 및 상태 유지 불량 | **가장 시급** (뒤로가기 시 필터 초기화, 탐색 단계 과다) |
| 테마 2. 입력 및 시각적 피드백 인지성 저하 | |
| 테마 3. 조작 원복 및 제어권 부재 | |

### 프로젝트 목표 (KPI)
1. 탐색 과업 3단계 이내 축소 및 재검색 시간 50% 이상 단축
2. 날짜·필터 조작 시 입력 오류 평균 0회
3. 뒤로가기·URL 공유 시 검색 필터 상태 보존율 100%
4. KWCAG 2.2 지침 및 KRDS 필수(P0) 규격 100% 충족

## 2. 타겟 페르소나 (Target Persona)

| 구분 | 박영희 (60대, 저시력·고령자) | 정우진 (30대, 모바일 기획자) |
|---|---|---|
| 상황 | 약한 저시력과 손떨림이 있으며 PC/모바일 웹을 이용함. 방문 전 특정 분관(북서울미술관)과 관람 예정일의 해설 일정을 사전 조회함 | 바쁜 직장인·문화 기획자로 모바일 중심으로 웹을 자주 이용함. 주말에 동료들과 방문할 분관별 해설 일정을 비교하고 URL 공유와 뒤로가기를 자주 사용함 |
| 주요 기대치 | • YYYY-MM-DD 도움말과 테두리·굵기·범례 등 시각 단서로 오작동 없이 인지<br>• 일괄 초기화 버튼으로 조작 실수를 손쉽게 수정 | • '날짜+분관' 복합 필터로 3단계 이내 신속 탐색<br>• 뒤로가기·링크 공유 시 이전 검색 필터 상태 완벽 유지 |
| 겪고 있던 불편함 | • 입력 형식 미명시로 오입력 발생<br>• 휴관일·선택일이 색상으로만 구분되어 구별 불가<br>• 개별 지우기 조작 피로 | • 뒤로가기 시 필터가 초기화되어 처음부터 재선택<br>• URL 상태 미저장으로 타인 공유가 번거로움 |

## 3. 핵심 사용자 여정 (Core User Journey)

```
[1단계: 진입 및 목적 설정]
 └ 화면 상단에 명확한 <label>과 '날짜 + 분관' 복합 필터바 노출
 └ 목적에 맞게 과업에 즉시 진입
      │
[2단계: 필터 & 날짜 설정]
 └ 분관 선택 → 날짜 입력창 선택
 └ 입력창 하단 YYYY-MM-DD 도움말 확인
 └ 달력에서 텍스트 굵기·테두리·범례(배지)로 구분된 날짜 상태를 확인하고 선택
 └ 오설정 시 '필터 일괄 초기화' 버튼 1회 클릭으로 원복
      │
[3단계: 결과 확인 & 상세 이동]
 └ 3단계 이내 조작으로 분관·날짜에 맞는 전시해설 목록 갱신
 └ 해설 시간 확인 후 상세 페이지로 이동
      │
[4단계: 뒤로가기 & 공유/유지]
 └ 뒤로가기 시 URL 쿼리 파라미터 동기화로 기존 검색 조건 100% 보존
 └ URL 복사·공유 시 동일한 검색 결과 화면 전달
```

## 4. 기능 요구사항 (Functional Requirements)

> **세부 스펙(색상 코드, 크기 등)은 다음 단계에서 확정 예정**입니다. 아래는 "어떤 기능을 어떻게 개선하는가" 수준으로 정의합니다.

| ID | 기능명 | 세부 기능 | 예외 처리 및 에러 로직 |
|---|---|---|---|
| FR-01 | 복합 필터 제공 | • 6개 분관 선택 드롭다운과 달력 컴포넌트를 통합 필터바로 제공<br>• 날짜는 시작일 범위 선택/단일일 선택 지원 | • 범위 선택과 단일일 선택의 적용 방식(전환 방법, 기본값 등) → **추가 확인 필요** |
| FR-02 | 필터 일괄 초기화 | • 선택된 모든 분관·날짜 조건을 1회 클릭으로 원복하는 '필터 일괄 초기화' 버튼 제공 | • 초기화 후 화면 상태(기본값 등) → **추가 확인 필요** |
| FR-03 | 입력 도움말 & 라벨 | • 입력 필드에 `<label>`을 1:1 연결<br>• 하단에 YYYY-MM-DD 형식 도움말을 상시 노출 | • 날짜 오입력 시 필터에 시각적 강조를 적용하고 "YYYY-MM-DD 형식으로 입력해주세요." 안내 |
| FR-04 | 다차원 상태 구분 | • 색상 외 시각 단서로 날짜 상태를 구분<br>  - 오늘: 두꺼운 테두리 + '오늘' 텍스트<br>  - 선택일: 반전 배경 + '선택됨' 범례<br>  - 휴관일: 사선 패턴 + '휴관' 배지 | • 세부 표현 방식은 다음 단계에서 확정 예정 |
| FR-05 | URL 상태 동기화 | • 필터 선택 시 URL 쿼리 스트링(예: ?branch=north&startDate=2026-10-24)을 실시간 동기화<br>• 뒤로가기·앞으로가기·URL 공유 시 검색 상태 100% 보존 | • 파라미터 누락·오류 시 처리 방식 → **추가 확인 필요** |
| FR-06 | 예외 처리 & 에러 로직 | • 0건/휴관일 선택 시 "선택하신 날짜는 정기 휴관일입니다." 안내 및 "가장 가까운 관람 가능일 보기" 대안 버튼 제공<br>• 네트워크 오류 시 "일정 정보를 불러오지 못했습니다. 잠시 후 다시 시도해주세요." 안내 및 재시도 버튼 제공 | • 날짜 오입력 안내는 FR-03 참조 |

### 추가 확인 필요 사항
- KWCAG 2.2 및 KRDS P0 100% 충족이 목표이나, 이를 뒷받침하는 개별 요구사항(키보드 조작, 스크린리더 안내 등)이 자료에 없음
- 원문 FR-06의 오류 강조 표현은 색상을 지정하고 있으나, 색상 단독 구분을 개선하는 프로젝트 방향과의 정합성 확인이 필요하여 색상 지정은 제외함

## 5. UI/UX 및 정책 요구사항 (UI/UX & Policy Requirements)

### 1) 공공언어 가이드라인
- IT 전문용어(쿼리, 파라미터, 컴포넌트 등) 사용을 금지하고 쉬운 우리말을 사용한다.
- 예: '검색 조건 초기화', '날짜 선택하기', '관람 가능일'

### 2) 시각적 우선순위
| 순위 | 요소 |
|---|---|
| 1순위 | '날짜 + 분관' 복합 필터바 및 실행/초기화 버튼 |
| 2순위 | 검색된 전시해설 일정 카드 (분관명, 전시명, 해설 시간) |
| 3순위 | 입력 포맷 도움말 및 범례 안내 배지 |

### 3) 레이아웃 및 반응형 규칙
- 모바일 터치 최소 타깃은 KRDS 표준 44pt × 44pt를 준수한다.
- 고대비·저시력 사용자를 고려하여 3px 이상의 선명한 포커스링을 제공한다.
- PC는 상단 고정 필터바, 모바일은 상단 접이식 복합 필터바를 제공한다.

※ 위 수치 외의 세부 디자인 스펙(색상 코드 등)은 **다음 단계에서 확정 예정**입니다.

## 6. 반응형 (Responsive)

### 1) 브레이크포인트
| 구분 | 범위 | 미디어쿼리 |
|---|---|---|
| 모바일 | 0 ~ 1023px | 기본 스타일 (미디어쿼리 없음) |
| 데스크탑 | 1024px 이상 | `@media (min-width: 1024px)` |

- **모바일 우선(Mobile First):** 기본 스타일은 모바일 기준으로 작성하고, 데스크탑은 `min-width: 1024px` 미디어쿼리로 확장한다.
- 미디어쿼리의 브레이크포인트 값은 px로 표기한다. (아래 단위 규칙의 예외)

### 2) 단위 규칙
- 레이아웃 구성 시 상대단위(`%`, `rem`)를 사용하고, 고정 px 너비는 지양한다.
- `em` 단위는 사용하지 않는다.
- 루트 font-size는 브라우저 기본값(100%, 1rem = 16px)을 유지한다.
  - `html`에 px 단위 font-size를 지정하지 않는다. (사용자 글자 크기 설정 존중)

### 3) 콘텐츠 최대 너비
- 데스크탑에서 콘텐츠 영역은 rem 단위 `max-width`로 상한을 두고 가운데 정렬한다.
- 구체적인 수치는 Figma 시안 전달 시 확정한다. (임시 기준: `80rem`)

### 4) 접근성
- 320px 너비(400% 확대 상당)에서도 가로 스크롤 없이 모든 콘텐츠와 기능을 이용할 수 있어야 한다. (KWCAG / WCAG 1.4.10 리플로우)
- 모바일에서 버튼·링크 등 터치 영역은 최소 `2.75rem`(약 44px) × `2.75rem`을 확보한다.

### 5) 디자인 전달 및 적용 원칙
- 반응형 상세 디자인은 구현 단계에서 사이즈별 Figma 링크로 전달한다.
- Figma 시안의 px 값은 시각적 결과를 맞추되, 구현 시 위 단위 규칙에 따라 상대단위(`%`, `rem`)로 변환해 적용한다.
  - 변환 기준: `rem = px ÷ 16` (예: 16px → 1rem, 44px → 2.75rem)

## 7. 성공 지표 (Success Metrics)

|---|---|---|

| 한 번에 탐색 성공 | 자료에 목표 수치 없음 → **추가 확인 필요** | 2명 중 1명 (50%) |

| 검색 상태 보존율 | 뒤로가기·URL 공유 시 100% | 100% (URL 동기화 검증 완료) |
| 재검색 시간 단축 | 50% 이상 단축 | 측정 결과 없음 → **추가 확인 필요** |

| 가설 판단 | – | 계속 (Go) |

### 유의사항
- **표본 한계:** 참여 인원이 2명이며, 두 페르소나(저시력·고령자, 모바일 이용자)에 해당하는 참여자인지 자료에 명시되지 않음 → **추가 확인 필요**
- **지표 해석:** '최종 과업 완수(100%)'와 '한 번에 탐색 성공(50%)'은 서로 다른 지표이므로 구분하여 해석해야 함
- **누락 데이터:** 현황표 세부 집계 수치가 원문에서 누락되어 있음 → **추가 확인 필요**
